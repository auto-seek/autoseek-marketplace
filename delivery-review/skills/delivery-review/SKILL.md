# 交付检查

1. 从用户要求和已确认的决策中提取验收条件，保留范围与限制。不要自行添加业务目标。
2. 读取实际交付物与相关资料，选取能证明关键行为的检查。已有有效结果可以复用，说明来源及适用范围。
3. 分别记录检查通过、检查失败、未检查。缺少输入、权限或运行环境时说明具体影响，不把计划、接单回执或队友的完成声明当作结果。
4. 对真实问题提供位置、触发条件、影响与建议修复。没有问题也可以直接说明，不为凑数量制造问题。
5. 输出简短交付结论：已完成的目标、产物位置、验证结果、剩余问题。完成所需检查后结束，不自行启动循环或额外外发消息。

默认只读；修改产物时以用户实际授权范围为准。自己实现的部分标为自检，不称独立审查。使用当前可用工具和权限，不更改模型或扩大权限。
