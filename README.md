# AutoSeek 官方市场

可安装、fork 和分享的工作团队与工具。一个 Git 仓库是一份市场，每个子目录是一份包；包可以包含团队模板、应用或技能。

| 包                                                              | 用途                                                                 |
| --------------------------------------------------------------- | -------------------------------------------------------------------- |
| [项目交付团队](project-delivery/README.md) (`project-delivery`) | 项目负责人、产品分析师、工程师、质量审查员一起把需求变为可验证的交付 |
| 交付检查 (`delivery-review`)                                    | 对照用户目标检查实际产物、验证证据和剩余问题；可单独安装             |

## 安装使用

1. 在 AutoSeek 插件市场添加 `https://github.com/auto-seek/autoseek-marketplace`，勾选“把此仓库订阅为市场”；已订阅则刷新。桌面内置目录是随安装包发布的快照，Git 订阅可获取最新目录。
2. 安装“项目交付团队”，选择“fork 模板”生成个人副本，再在目标项目下用它创建团队。
3. 先给项目负责人一个具体任务，或者进入“交付协作”部门群，@ 需要参与讨论的成员。交付检查技能是可选工具，团队模板不依赖它。

同一个成员既执行任务，也参与私聊和群聊。岗位描述分配职责，模型与权限由用户配置。点击部门名称进入群聊，点击图标展开或收起；只有被 @ 的成员会响应。每次补送最近最多 100 条、合计最多 20,000 字符的群记录。

模板强调真实资料、实际产物和可核对结果。工作方式可以不同：负责人重取舍、分析师重证据、工程师重实现、审查员重缺陷。示例不配置虚构人物身份、剧情、角色卡、立绘或配音。

## 贡献一份包

1. 从团队模板页导出团队包，将完整目录放在市场根目录下。保留导出产生的 `team-package.json` 和资源文件；不要提交私人对话、凭据或业务数据。
2. 编辑 `.codex-plugin/plugin.json` 的名称、说明和版本。团队包用 `autoseek.templates` 声明，应用用 `autoseek.apps`，技能用 `skills`；路径相对于包根。
3. 在 `.agents/plugins/marketplace.json` 的 `plugins` 中登记名称与本地相对路径。提交可复现的使用步骤、实际交付例子和许可说明。
4. 更新已发布内容时提高包版本；相同版本不能替换为另一份内容。应用仍经过原有宿主能力与信任检查。

```json
{
  "name": "my-work-team",
  "version": "1.0.0",
  "description": "A team for a specific work task",
  "autoseek": { "templates": ["./"] }
}
```

fork 的个人模板独立保存。目录更新、包停用或卸载不会覆盖个人副本。旧版夜班观测站与场景写作示例已从当前市场目录撤下；已有团队、聊天与 fork 可继续保留，此变更不会迁移或删除它们。
